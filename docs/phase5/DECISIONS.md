# Phase 5 Decisions — Book 1 / S4615

| Decision | Rationale / evidence |
|---|---|
| Use SAP GUI for Customizing objects where an API write contract was not proven. | Company Code, Sales Organization, assignment, and chart-assignment work used the evidenced SAP GUI paths. |
| Use `API_BUSINESS_PARTNER` for Customer operations. | Live metadata, lookup, CSRF, role POSTs, and customer readbacks were verified. |
| Prefer `API_PRODUCT_SRV` for Product before considering BAPI/RFC or GUI. | The live product service responds and confirmed `P615-400` not found; no validated live RFC execution channel exists. |
| Keep BPAB-generated SAP keys; do not force the Book ID as BusinessPartner. | BPAB uses internal number range `BP`, `1000000000..1999999999`. |
| Store the logical customer ID separately from the SAP BP ID. | The logical Book ID is `C615-D00`; SAP created BP `1000000114`. The mapping is known but not yet persisted. |
| Record `C615-D00 → 1000000114` as the customer mapping. | This is the live-created BP representing the logical Book customer; do not create a duplicate. |
| Keep the manually created customer address. | OData address creation failed with R1/000 `CHECK_TABLE_MISSING`; SAP GUI address entry was completed and current standard address `1557` survived exit/re-entry verification. Never recreate it. |
| Company Code 1010 uses chart `CABE`. | 1010 was copied from `BE01`; its chart was assigned through OB62 and the `1010 → CABE` value was independently confirmed after re-entry. |
| Use GL account `400000` for the 1010 customer company-code extension after its 1010 segment exists. | Live read-only `I_GLAccount` evidence identifies `400000` as an active CABE customer-reconciliation account (`D`) in BE01 and LU01; the English account name is `Receivables: Custom.`. More specialized CABE candidates are bills of exchange, down payments, doubtful receivables, TR-LO, or rent deposits. |
| Do not call the GL-account UI service's copy actions without a proven payload contract. | `UI_GLACCOUNTINOPERATCOA_02` metadata marks all relevant entity sets non-creatable/non-updatable. Although `CopyCompanyCodeAssignment` is exposed as POST, its JSON-string payload semantics are not documented by metadata or repository evidence. |
| Treat the exact sales area `1010/10/00` as a separate customizing dependency. | The three component assignments are live-verified, but the `A_CustomerSalesArea` POST was rejected by SAP's Sales Organization / Distribution Channel / Division plausibility check. |
| Sales area `1010/10/00` is complete and accepted by master-data validation. | The human checkpoint created the exact combination under `A4HK908422`; the subsequent `A_CustomerSalesArea` POST and independent readback succeeded. |
| Keep Product unit `PC`; do not translate it to `289` or `/PC`. | Live `A_ProductUnitsOfMeasure` reads contain products whose `AlternativeUnit` and `BaseUnit` are exactly `PC`. `289` and `/PC` are separate live values and are specific to other products, including the technical template. |
| Mark Product OData creation unavailable. | The exact desired root POST to `API_PRODUCT_SRV/A_Product` returned HTTP 400 `Créer n'est pas autorisée pour l'entité`; the subsequent lookup remains missing. |
| Use plant `1710` for Product `P615-400`. | The approved template FG228 uses plant/supplying plant 1710, and the exact assignment `1010/10/1710` was subsequently live-verified by the human checkpoint. |
| Do not infer BE/MWST classification from US/UTXJ. | Live MM01 shows separate BE/MWST and US/UTXJ rows. US has classification `1`, while BE is blank; the Product API contains no existing BE/MWST row to establish an inheritable value. |
| Do not choose a BE/MWST code from the F4 list without functional evidence. | The live value help offers codes `0`–`6` with blank descriptions. Active `FERT` Product API evidence contains both MWST `0` and `1` for other countries, while the closest intended technical family yielded no tax row; neither code is deterministic for Belgium. |
| Treat material `10000286` as not created. | Fresh independent Product API readback returned root `404` and no plant, sales-delivery, or tax rows; the only SAP GUI session is now `OVK4`, so the earlier unsaved MM01 buffer is unavailable. Never persist the logical mapping until a later save and fresh readback succeed. |
| Record `P615-400 → 10000287` as the Product mapping. | SAP confirmed creation, and independent `API_PRODUCT_SRV` readbacks verified the root, Plant `1710`, Sales `1010/10`, and `BE/MWST/1` records with all required values. |
| Resolve logical master-data identities only on a runtime payload copy. | The canonical Book IDs remain immutable; verified mappings produce `SoldToParty=1000000114` and `Material=10000287` for prechecks and execution. |
| Do not retry the BV order until live pricing determination is proven. | The first controlled POST returned HTTP 400 V1/212 for `1010/10/00 + A + 02` and created no order. S4620 canonical evidence for `A + 1 → RVAA01` is informative but does not prove the live OVKK state or authorize changing the customer procedure. |
| Reject `1010/10/00 + A + 1 → RVAA01` as an OVKK source. | A direct human read-only OVKK positioning found no exact row and moved to `140C`; canonical course data does not override missing live customizing. |
| Use live OVKK row `1710/10/00 + A + 02 → A17J02` as the pricing-determination source. | A direct read-only OVKK observation confirmed the exact row and assigned procedure. The target copy changes only Sales Organization to `1010`; `10/00/A/02` and `A17J02` remain unchanged. |
| Assign Fiscal Year Variant `K4` to Company Code `1010`. | The post-OVKK controlled POST failed with SAP `KI 268`. Fresh `API_COMPANYCODE_SRV` reads prove `1010.FiscalYearVariant` is blank and approved template `BE01.FiscalYearVariant` is `K4`; this is a direct missing copied setting, not a guessed value. |
| Do not guess the T184 item category for `BV/CB04`. | After `K4` was verified, SAP V1/320 proved the exact missing determination. Existing `CS` orders `1` and `148` prove `FG228/CB04 → CBTA`, but no live `BV` order or direct T184 source-row read yet proves that `CBTA` is the approved target value. |
| Use `CS/CB04/blank/blank → CBTA` as the approved T184 source. | Direct read-only VOV4/T184 verification confirmed the exact row. The target `BV/CB04/blank/blank → CBTA` changes only the sales-document type and preserves all other determination keys and the item category. |
| Persist and reuse the allowlisted VOV4 contract for `BV/CB04`. | The target was saved and independently found at absolute row `392`. Future books may use the same generic contract mechanism, but each source and target tuple must remain explicitly evidence-backed and allowlisted. |
| Extend Product `10000287` with accounting data before another Sales Order retry. | SAP V4/210 and targeted API GETs prove the valuation view is absent. FG228 provides the exact technical-template valuation evidence for valuation area `1710`; no accounting value may be invented. |
| Do not invent the missing FINSC currency-type `30` conversion rule. | MM01 stopped with C+899 before Save. Live evidence proves the affected context is Company Code `1710`, but the exact `FINSC_001A` source-currency/exchange-rate/date fields are not exposed by an existing read contract. |
| Persist the proven FINSC rule `1710/30/10/M/2` with real-time conversion. | The approved values were saved under `A4HK908422`; independent `SE16N` readback confirms the exact stored `FINSC_001A` row. The UI currency display is derived and is not a `FINSC_001A` field. |
| Stop before any Material Ledger initialization, migration, or global currency change. | After the FINSC correction, MM01 raises C+039 before accounting fields are available. SAP states that valuation area `1710` now differs from its productive-startup currency configuration. The message supplies no procedure, and changing a global currency definition could affect unrelated company codes. |
| Continue using customizing transport `A4HK908422` where applicable. | This is the S4615 Training Setup transport already used for verified customizing changes. |
| Keep S4615 preloaded-document exercises explicit rather than substituting a technical pilot document. | Targeted user-`00` Sales Order GETs returned no rows for exact Book references `A1`, `A3`, `A4`, `A5`, `A6`, and `A10`; no unrelated order or invoice may stand in for them. |
